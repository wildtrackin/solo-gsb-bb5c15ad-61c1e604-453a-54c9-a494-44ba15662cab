# HTTP 路由冲突实验室

基于 **Node.js + Express + 原生前端**（零前端构建）的交互式实验室：
按优先级维护一组 HTTP 路由规则，系统实时判定规则之间的**完全遮蔽**与**部分重叠**，
并为每个冲突生成两条规则**都能命中的最短示例路径**（段数相同并列时取字典序最小者）。
拖动行调整顺序后结果立即重算。对可修复的完全遮蔽，系统会**生成修复方案**
（确定性的建议顺序），支持预览后一次应用。支持规则集的 JSON 导入 / 导出。

## 一条命令启动

```bash
docker compose up --build
```

然后打开 <http://localhost:3000>。

> 不想用 Docker 时：`npm install && npm start`，同样访问 <http://localhost:3000>。

## 路径语法

| 段类型     | 示例               | 匹配范围                         |
| ---------- | ------------------ | -------------------------------- |
| 静态段     | `/users/profile`   | 字面匹配该段                     |
| 参数段     | `/users/:id`       | `:id` 匹配**一个非空**段         |
| 通配符段   | `/assets/*`        | `*` 匹配**零个或多个**任意段     |
| 根路径     | `/`                | 仅匹配空段序列                   |

- 规则在列表中的**自上而下顺序即匹配优先级**（与 Express 的注册顺序一致）。
- 请求方法可选择常见方法或 `ALL`；`ALL` 表示与任意方法比较。不同具体方法的规则互不冲突。
- `*` 必须独占一个路径段（如 `/assets/*`），段内混写（`/assets/*.css`）会报语法错误。

## 冲突类型

- **⛔ 完全遮蔽（shadow）**：高优先级规则能匹配的路径集合 ⊇ 低优先级规则，
  因此低优先级规则永远不会被执行。
  例：`GET /*` 位于 `GET /health` 之前。
- **⚠️ 部分重叠（partial）**：两条规则都不是对方的超集，但存在同时命中的路径。
  例：`GET /a/*` 与 `GET /*/b`，同时命中的最短路径为 `GET /a/b`。

每个冲突卡片展示双方规则、关系说明，以及最短示例请求（点击可复制）。
列表中对应规则行会高亮并标注“遮蔽 N 条 / 重叠 N 条”。

**最短示例的约定**：需要由参数或通配符自由取值的段统一使用最小段值 `a`；
在段数最少的前提下，按 UTF-16 字典序选择最小的路径，保证结果唯一确定。

## 修复方案（建议顺序）

存在完全遮蔽时，分析结果顶部会出现 **🛠 修复方案** 卡片：

- **约束图**：把“更具体的规则必须排在严格覆盖它的规则之前”转化为约束边
  （`L(A) ⊋ L(B)` ⟹ 边 `B → A`），语言等价（互相覆盖）的规则先经并查集合并成组，
  在组间约束图上做 Kahn 拓扑排序，每步选取“组内最小原始索引”最小的可用组——
  因此建议顺序是**确定的**，且尽量保持原有相对顺序；无效规则固定在原槽位。
- **调整前后位置**：卡片列出每条需要移动的规则（`#调整前 → #调整后`）。
- **不可避免的遮蔽**：语言等价的规则（如 `GET /x/:id` 与 `GET /x/:name`）
  无论怎么排序都互相遮蔽，这部分会被如实计入“无法通过排序消除”的数量并单独列出，
  **不会伪装成已修复**——需删除或修改重复规则才能消除。
- **预览 → 一次应用**：点击“预览新顺序”后，左侧规则列表切换为建议顺序的静态预览
  （标注每条规则的原位置）；确认后点“应用新顺序”一次性重排，
  随后沿用现有的实时分析与 localStorage 本地保存。

## JSON 导入 / 导出

导出文件格式（也兼容直接导入裸数组）：

```json
{
  "format": "route-conflict-lab/v1",
  "exportedAt": "2026-09-19T00:00:00.000Z",
  "rules": [
    { "method": "GET", "path": "/api/*" },
    { "method": "GET", "path": "/api/users/:id" }
  ]
}
```

规则在 `rules` 数组中的顺序即优先级。页面会自动把当前规则集保存到浏览器 localStorage。

## HTTP API

- `POST /api/analyze` — 请求体 `{ "rules": [{ "method": "GET", "path": "/x/:id" }] }`，
  返回逐条规则的校验/冲突标注、冲突列表（含 `type`、`higher`、`lower`、`example`）、
  汇总计数，以及修复方案 `fix`：

  ```json
  {
    "fix": {
      "order": [2, 1, 0],
      "changed": true,
      "moves": [{ "index": 2, "id": 2, "method": "GET", "path": "/api/users/:id", "from": 2, "to": 0 }],
      "unavoidableShadows": 0,
      "equivalentPairs": [],
      "equivalentGroups": [],
      "shadowsBefore": 3,
      "fixableShadows": 3
    }
  }
  ```

  - `order`：完整排列，`order[新位置] = 原索引`，直接 `order.map(i => rules[i])` 即可应用；
  - `moves`：位置变化的规则（`from`/`to` 为 0 基索引）；
  - `unavoidableShadows` / `equivalentGroups`：排序无法消除的遮蔽及其等价规则组；
  - `shadowsBefore` / `fixableShadows`：当前遮蔽总数与可通过排序修复的数量。
- `GET /api/health` — 健康检查。

## 实现说明

分析核心位于 `lib/analyzer.js`（纯函数，无依赖）：每个路径模式被建模为带 ε 边的 NFA
（`*` 为“ε 跳过 + 任意段自环”），通过子集构造得到 DFA。

- 遮蔽判定：在两个模式的乘积 DFA 上搜索“B 接受而 A 不接受”的可达状态；
- 交集示例：在乘积 DFA 上按段数做 BFS，同层边按段值字典序处理，首个到达的共同接受状态
  即为“段数最少、并列字典序最小”的示例路径；
- 修复方案：对方法兼容的规则对记录双向覆盖关系，语言等价的规则并入等价组
  （组内遮蔽不可消除），严格覆盖转化为“具体在前”的约束边，
  在等价组压缩后的约束图（必为无环图）上做确定性拓扑排序，输出建议顺序。
